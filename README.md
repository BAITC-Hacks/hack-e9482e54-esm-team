# Beeline: LLM-агент тарифных кампаний

LLM выбирает пилотные эксперименты, статистическая модель обновляет оценки,
численный планировщик формирует до 10 кампаний в пределах бюджета и охвата.
Все данные синтетические. Локальный результат не прогнозирует балл судейства.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Установите OPENAI_API_KEY в окружении, не записывайте ключ в репозиторий.
export OPENAI_MODEL=gpt-4.1-mini
python check_llm.py
python run_agent.py
python local_eval.py --runs 10
python make_submission.py
python -m unittest -v
```

`run_agent.py` сохраняет решения, объяснения и счёт в `run_report.json`.
Локальный `.env` загружается автоматически; переменная из окружения имеет приоритет.
`check_llm.py` выполняет живой запрос без кэша, печатает безопасный статус и
возвращает ненулевой код при ошибке. Наличие ключа само по себе не означает доступ к API.
Скрипты организаторов сохранены без изменений. Для HTTP используется стандартная
библиотека Python; дополнительный SDK не нужен.

## Работа LLM

`llm_planner.py` использует OpenAI Responses API и
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Модель получает до 30 агрегированных кандидатов, остатки лимитов и прошлые
наблюдения. Выбирает до пяти следующих пилотов и их размеры, объясняет выбор.
Эти решения исполняются через `env.run_pilot`. Следующая партия учитывает результаты.
Максимум четыре обращения, таймаут — 25 секунд, без повторов при ошибке.
Индивидуальные профили и ID абонентов в API не передаются.

Код проверяет кандидатов, размеры выборок, лимиты. Модель не исполняет произвольный
код и не управляет бюджетом напрямую. При отсутствии ключа, ошибке API, отказе
или некорректном ответе работает статистическая резервная стратегия.
После ошибки новые API-запросы в этом прогоне отключаются.

`AGENT_LLM_MODE`: `auto` (по умолчанию), `off`, `replay`.
`OPENAI_MODEL` позволяет выбрать доступную вашему аккаунту модель с поддержкой
Responses API и JSON Schema.

## Стратегия и ограничения

- Кандидат: текущий тариф × ARPU-сегмент × целевой тариф.
- Историческая медиана изменения ARPU даёт слабую предварительную оценку.
  Коэффициент 0.10 — эвристика, не оценка конверсии из истории переходов.
- Дисперсия наблюдения `0.804² / n` взята из публичного интерфейса среды.
  Нормальная предварительная оценка имеет стандартное отклонение 0.15.
- Резервная разведка учитывает выручку, среднее, неопределённость, число измерений
  и разнообразие ячеек аудитории.
- Первые две партии исследуют гипотезы, следующие две подтверждают измеренных
  претендентов. Непроверенные кандидаты не вытесняют подтверждение лидеров.
  Резервная стратегия использует пилоты по 200 человек; LLM выбирает 100–200.
- Для финального плана используется `mean - 1.64 * standard_error`.
  Это поправка на риск, а не гарантия прибыльности или строгий доверительный интервал.
- Каналы сравниваются по приросту и цене; перенос на звонки консервативно ограничен
  из-за неизвестного насыщения конверсии.
- Жадный выбор учитывает дефицит бюджета, но не гарантирует глобальный оптимум.
  Финальные аудитории не пересекаются. Пересечения с пилотами точно неизвестны.
- Для финального плана резервируются 1 000 контактов и 10 000 у.е.
- Если прибыльных вариантов нет, выбирается проверенный push-вариант с наибольшей
  консервативной оценкой, чтобы вернуть обязательную кампанию. Убыток возможен.

## Воспроизводимость

Онлайн-ответы LLM не гарантированно повторяемы. Успешные ответы кэшируются
по хешу запроса, модели, промпта и схемы в `.llm_cache/`.
Повтор с тем же seed и кэшем использует те же решения. `AGENT_LLM_CACHE` меняет
каталог. Ключ не сохраняется. Кэш по умолчанию не добавляется в Git.

Для воспроизводимой генерации без кэша:

```bash
AGENT_LLM_MODE=off python make_submission.py
AGENT_LLM_MODE=off python local_eval.py --runs 10
```

Для сдачи именно LLM-стратегии нужны сохранённый кэш и одинаковый режим `replay`
при генерации и проверке. Передачу кэша и настройки запуска нужно согласовать
с организаторами. При промахе кэша `replay` использует резервную стратегию без сети.
Приложенный `submission.csv` сгенерирован в режиме `off`.

## Проверки

`test_agent.py` проверяет ответ API, таймаут, отказ модели, кэш, влияние LLM
на выбор пилота, лимиты и повторяемость резервной стратегии. Живой вызов требует
вашего API-ключа; тесты используют подставной HTTP-транспорт.
`--runs 10` без LLM проверяет устойчивость к шуму мока, а не пользу модели.
Для измерения пользы LLM сравнивайте `auto` и `off` на одинаковых seed.

Первый вариант на seed 0–9 давал 8 прибыльных прогонов из 10, медиану +240 985
и минимум −459 092 у.е. После выделения подтверждающих пилотов и усиления
поправки на риск: 10/10, медиана +654 489, минимум +286 903 у.е.
Эта выборка использовалась при разработке, поэтому добавлена отдельная проверка
на seed 10–29 и сравнение с шаблоном на тех же seed:

```bash
python verify_strategy.py
```

Она сохраняет `validation_results.json` и проверяет отсутствие обрезания кампаний,
лимиты денег/контактов/пилотов и количество финальных кампаний.
Результат на seed 10–29: агент 20/20 прибыльных прогонов, медиана +426 487,
минимум +126 407 у.е.; шаблон 0/20, медиана −387 245 у.е. Максимальное время
локальной оценки агента без API — 1.16 секунды. Все 10 автоматических тестов прошли.
После обновления локального ключа `check_llm.py` успешно проверил живой ответ
`gpt-4.1-mini` с заданной JSON-схемой. Полный онлайн-прогон на seed 42 также
завершён: четыре ответа модели, 19 пилотов, одна финальная кампания,
4 167 контактов, расходы 38 754 у.е., чистый результат +1 277 417 у.е.
Резервная стратегия на том же seed: +634 000 у.е.; разница +643 417 у.е.
Все лимиты соблюдены, повтор из кэша воспроизводит пилоты, кампании и результат.
После согласования выполнены ещё два онлайн-прогона. Первое решение совпало
по контексту и использовалось из кэша, остальные три решения на каждом новом
seed получены через API: всего шесть новых запросов.

| Seed | Резервная стратегия, у.е. | LLM, у.е. | Разница, у.е. |
|---|---:|---:|---:|
| 42 | 634 000 | 1 277 417 | +643 417 |
| 10 | 507 062 | 1 879 365 | +1 372 304 |
| 11 | 462 120 | 1 246 471 | +784 351 |

LLM выиграла в 3/3 парных сравнениях; медиана результата +1 277 417 против
+507 062 у.е. у резервной стратегии. Во всех трёх случаях проверены лимиты
и точное воспроизведение пилотов, кампаний и результата из кэша.
Три seed и одна мок-модель недостаточны для вывода об устойчивом преимуществе
на судействе. Это проверка работы интеграции и предварительное сравнение.

Парное сравнение и объяснения модели сохранены в `llm_validation_results.json`,
LLM-кампания — в `submission_llm.csv`. Основной `submission.csv` пока содержит
резервный вариант, описанный выше. Для повторения проверенного LLM-прогона без сети:

```bash
python compare_llm.py --seeds 42 10 11 --replay-only
```

Требуется сохранённый локальный `.llm_cache/`. Скрипт проверяет совпадение
пилотов и кампаний при повторе; при неполном кэше завершает проверку с ошибкой.
Онлайн-сравнение с новыми seed выполняется командой `python compare_llm.py`
(до четырёх запросов на seed, по умолчанию seed 42, 10, 11).

Сдавайте `agent.py`, `llm_planner.py`, `requirements.txt`, `submission.csv`
и историю `data/change_tariff.csv`. Агент не импортирует мок, скоринг
или скрытую модель эффектов.
