# Beeline: агент тарифных маркетинговых кампаний

Агент выбирает пилоты, обновляет оценки по наблюдаемым результатам и возвращает
до 10 кампаний с учётом бюджета, охвата и неопределённости. Данные синтетические.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Команды запускаются из корня репозитория. Скрипты среды и скоринга организаторов
оставлены без изменений. `submission.csv` генерируется последней командой.

## Состав

- `agent.py` — класс `Agent` с методом `act(env)`, статистика и выбор кампаний.
- `llm_planner.py` — выбор экспериментов через OpenAI Responses API.
- `llm_responses/` — сохранённые ответы модели для воспроизводимости.
- `submission.csv`, `requirements.txt`, `README.md`, `.gitignore`.
- `local_eval.py`, `make_submission.py`, `environment.py`,
  `mock_environment.py`, `scoring_core.py` — локальная проверка организаторов.
- `customer_profile.csv`, `data/change_tariff.csv`, `data/dict_tariff.csv` —
  данные, используемые текущим решением и локальной средой.

## Как работает агент

Кандидат — текущий тариф × ARPU-сегмент × целевой тариф. История переходов
задаёт слабую предварительную оценку, но не вероятность конверсии.
Первые две партии пилотов исследуют гипотезы, следующие две подтверждают
измеренных претендентов. Модель получает агрегаты и прошлые наблюдения,
выбирает до пяти пилотов по 100–200 человек. Индивидуальные профили не отправляются.

Результаты обновляют статистические оценки с дисперсией наблюдения `0.804² / n`
согласно публичной среде. Финальный план использует поправку на риск
`mean - 1.64 * standard_error`, сравнивает каналы по стоимости и ожидаемому
приросту. Выбор жадный, глобальная оптимальность не гарантируется.
Финальные аудитории не пересекаются между собой; пересечения с пилотами возможны.

## LLM, ключ и воспроизводимость

Модель по умолчанию — `gpt-4.1-mini`; настройка — `OPENAI_MODEL`.
Ключ берётся только из `os.environ["OPENAI_API_KEY"]`. На судействе его задают
организаторы. `.env` автоматически не загружается и не входит в сдачу.
Для локальных новых API-вызовов экспортируйте ключ в окружение терминала.

Режимы `AGENT_LLM_MODE`: `auto` (по умолчанию), `off`, `replay`.
В режиме `auto` сначала проверяются записанные ответы, затем API; при отсутствии
ключа или ошибке используется статистическая стратегия. В `off` LLM полностью
выключена. В `replay` используются записи и резервная логика, без сети.

`llm_responses/` содержит 10 фактически полученных ответов модели, а не скрытые
эффекты или готовые кампании. Ответ применяется только при точном совпадении
хеша полного запроса, включая промпт, модель, схему, наблюдения и лимиты.
Изменение результатов пилотов меняет запрос. Новые ответы сохраняются в
локальном `.llm_cache/`, который исключён из Git.

Комплектные ответы воспроизводят `submission.csv` на seed 42 без API-ключа
и локального кэша. Папку `llm_responses/` нужно сохранять в репозитории.
Смена модели, промпта или зависимостей может потребовать повторной генерации CSV.

## Ограничения и ошибки

Максимум четыре обращения к модели, сетевой таймаут 25 секунд, без повторов.
После 210 секунд не начинается новая партия, после 240 секунд — новый пилот.
Эти проверки не прерывают зависший вызов самой среды. Ошибки HTTP, таймауты,
отказ модели и неправильный JSON перехватываются с переходом на статистику.
Агент не импортирует скоринг или мок и не извлекает скрытые атрибуты среды.

В отчёте «Кампаний: 20» на seed 42 означает 19 пилотов и одну финальную кампанию.
Лимит 10 относится к списку, возвращаемому `act`.

## Результаты проверок и пределы

На seed 42 полный LLM-прогон дал +1 277 417 у.е., 19 пилотов, одну финальную
кампанию, 4 167 контактов и расходы 38 754 у.е. На seed 10 и 11 результат
составил +1 879 365 и +1 246 471 у.е. Это мок-среда, не прогноз балла судейства.

Перед очисткой репозитория выполнены 16 автоматических тестов и 240 независимых
стресс-прогонов без API. Технических нарушений не было, но финансовая устойчивость
не подтверждена: ошибочная история, редкие прибыльные переходы и слабый сигнал
приводили к убыткам. При полностью убыточных переходах агент пока недостаточно
ограничивает ущерб разведки. Вспомогательные тестовые скрипты и отчёты удалены
при подготовке минимального комплекта; эти результаты приведены как история проверки.

Не добавляйте в Git `.env`, ключи, `.venv/`, `__pycache__/` и `.llm_cache/`.
